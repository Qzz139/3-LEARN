# 抓放 demo 实机调试记录（2026-09-18）

## 初始化与首次抓放

用户在 App 移除机械臂配置后，独立舵机命令可以执行。
初始化反馈：抓夹侧约605（目标601）、底盘侧1073，抓夹打开，底盘未转动。

首次完整测试收到17、19、19 mm三次红外反馈，按20 mm阈值触发夹紧。
用户确认夹住网球且没有碰撞。随后旧内收目标552未通过反馈验收，程序停止并请求红灯；
尚未右转或放置。停下后只读反馈约602/1049。

552来自参考模型推算，不是这台设备的实测内收位置，不应重试。
该值对应SDK角度−83°，而初始1073对应9°，差约92°。

## 小步确认方向

抓夹释放后，保持抓夹侧602，不再向它发送定位命令；底盘不转动。
底盘侧9°→14°两次到位，随后逐步19°→24°→29°，每步5°、停2秒，均通过反馈验收。

| SDK命令 | 预期DDS值 | 本次到位反馈 |
| --- | --- | --- |
| 9° | 1075 | 1073–1078 |
| 14° | 1104 | 1101 |
| 19° | 1132 | 1128 |
| 24° | 1161 | 1155 |
| 29° | 1189 | 1183 |

用户最终更正观察为：数值增加时**内收并下沉**，并非抬高。
用户进一步明确：**外伸必须是抓夹最低点，内收必须抬高，抓夹侧舵机保持固定。**
因此上述内收并下沉的动作不合格，不能以离地间隙足够为理由继续使用。
1073不能作为已确认的最低外伸目标；552及29°均不能作为有效内收目标。
配置中的外伸/内收目标已清空，不再自动执行这些姿态。所有动作测试停止；
先核对物理舵机对应关系及运动几何，再确定目标，尚未完成完整抓放周期。

日志保存于 `records/grasp_tests/20260918/`，包括初始化、首次失败及各次小步测试。
Jetson系统时间未同步，日志UTC显示1970年；日期按工作站记录。

## 官方数值依据

[Servo.moveto官方接口](https://robomaster-dev.readthedocs.io/en/latest/python_sdk/robomaster.html#module-robomaster.servo)
接收−180°至180°的整数绝对角度。
[官方SDK源码](https://github.com/dji-sdk/RoboMaster-SDK/blob/master/src/robomaster/servo.py)
将命令角度编码为 `(angle + 180) * 10`。此编码不是DDS反馈编码器值。

实机get_angle查询与DDS核对：564对应99.1°、1078对应189.4°，支持DDS每1024单位约180°。
初始定位及小步试动也验收了当前转换。官方接口通用数值范围不能替代机械装配的实际可达范围；
官网没有指定552为此装配姿态的内收目标。
