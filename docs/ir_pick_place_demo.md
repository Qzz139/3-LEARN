# 红外单次抓取—放置 demo

动作顺序固定为：

1. 抓夹连杆侧舵机（ID2、反馈槽1）先定位到记录值 `raw=1073` 附近，随后不再向它发送位置命令。
2. 底盘侧舵机（ID1、反馈槽0）外伸到抓夹最低点，夹爪松开，进入初始态。
3. 第一号红外原始反馈连续 3 次为正数且不大于 20 mm 后，夹爪收紧。
4. 底盘侧舵机内收并抬高抓夹，底盘右转 90°。
5. 底盘侧舵机外伸，夹爪松开放置；机械臂内收，底盘左转 90°。
6. 底盘侧舵机外伸、夹爪保持松开，回到初始态。

**外伸必须是抓夹最低点，内收必须抬高；不能接受内收过程中下沉。**
抓夹侧舵机先设置到记录值，随后固定；不得通过转动它来补偿高度。

`601/1073` 和末端位置 `209/68 mm` 只是记录姿态，不能证明外伸最低点。
旧目标 `552` 以及9°至29°测试实际发送给了抓夹侧ID2，违背抓夹侧固定要求，
不能当作底盘侧的方向或范围标定。现将 `base_extended_raw`、`base_retracted_raw` 清空为 `null`，
不再复用这些数值。默认配置可预览，执行前会因缺少姿态目标退出，不发送机器人命令。
这不恢复 `calibration_verified` 开关保护；该字段仍仅用于提示。

只读查询确认 ID1/2 对应反馈槽0/1。交换测试中用户确认恢复ID2时实际运动的是抓夹侧，
据此纠正原先写反的角色：ID2为抓夹侧，固定在原记录1073；ID1为底盘侧，原记录601。
交换后ID2反馈1075、ID1测试600后反馈599，均到位。ID1当时原本就在601附近，
因此尚未确定底盘侧完整运动范围及满足高度要求的外伸/内收目标。
当前单元测试只验证软件命令顺序，不证明机械臂满足高度要求。

红外安装在夹爪上方并朝夹取方向，触发依据是传感器原始读数，不是校准后的物理距离。
当前使用反馈槽 0，可通过 `infrared.feedback_slot` 改端口。
大疆标称红外测距量程为 `0.1–10 m`，20 mm 超出标称量程。
本次网球实测：人工摆放约3 cm时读数8–16 mm，约4 cm时27–34 mm，且旧30 mm规则
在4 cm组出现连续3次满足条件。按用户要求将原始触发阈值降低为20 mm。
这不是实际2 cm的测距标定；重放重复性及水瓶仍待验证，详见[实测说明](ir_distance_measurement.md)。

DDS 舵机反馈使用编码器单位，`1024` 对应 `180°`，与动作协议的十分之一度编码不同。
实机只读核对得到 `DDS 564 → get_angle 99.1°`、`DDS 1078 → get_angle 189.4°`，
ID 1/2 分别对应反馈槽 0/1。`Servo.moveto` 命令转换为
`round(raw * 180 / 1024 - 180)`。抓夹侧记录值1073对应命令9°，预期DDS1075、
动作协议编码1890；单位换算正确不代表姿态目标正确。
反馈验收围绕配置中的原始目标值，允许 `8` 个 raw 单位误差。

大疆[官方 EP Core FAQ](https://www.dji.com/support/product/robomaster-ep-core)
在 “How can the DJI 1240BA servo be used?” 中明确说明：组装配置为机械臂后，
不能作为独立舵机控制；恢复独立舵机控制须先在 App 的 Settings → Extension Module
中移除机械臂配置。同一 FAQ 给出了红外 `0.1–10 m` 标称量程。
本 demo 要求单个舵机控制，因此需要这一配置变更；角度/速度模式切换并不能替代它。
此前处于机械臂配置时，EP 拒绝 ID 1 同姿态定位（返回码 1），位置模式设置也被拒绝；
不能将此问题当作网络断开或动作等待超时。程序会记录动作状态并停止、亮红灯，
不会自动改用会联动两个关节的机械臂末端控制。

YOLO 使用独立推理进程，默认模型为 `yolo26m.pt`。检测结果写入每次运行目录的
`detections.jsonl`，抓放状态机不读取检测结果；模型缺失、加载失败或推理异常均不会触发
抓放失败。

Ubuntu 启动脚本优先使用 Jetson 上现有的
`/home/robot/venvs/yolo_ros2/bin/python`（该环境同时包含 RoboMaster SDK 与
Ultralytics）；也可通过 `EP_DEMO_PYTHON=/path/to/python` 指定环境。

先预览配置和动作：

```bash
./scripts/run_ir_demo_ubuntu.sh
```

设置满足高度要求的姿态目标后，实机运行：

```bash
./scripts/run_ir_demo_ubuntu.sh --execute
```

程序只等待红外原始反馈满足配置的20 mm阈值，不自动向前行驶。夹爪从夹取开始保持收紧，
直至放置时松开。正常序列完成不等于已确认夹持成功，需观察目标是否被实际搬运。

测试（不连接机器人）：

```bash
python3 -m unittest discover -s tests -v
bash -n scripts/run_ir_demo_ubuntu.sh
```

仓库已包含普通官方权重 `models/yolo26m.pt`，程序优先从该文件加载，无需在 EP 网络上
下载。文件大小和 SHA-256 已核对
[官方 YOLO26 发布信息](https://github.com/ultralytics/assets/releases/tag/v8.4.0)，
来源及校验值保存在 `models/yolo26m.source.json`。Jetson 已完成静态照片推理验证，
照片中的球检测为 `sports ball`，置信度约 0.955；尚未验证实时视频检测效果。

程序捕获异常或动作超时后，先请求停止底盘、底盘侧舵机与夹爪，再请求底盘装甲 LED
常亮红色；异常路径不会自动回初始态。网络断开或进程被强制终止时，无法保证停止和
LED 命令送达。正常结束后机械臂外伸、夹爪松开并熄灭底盘 LED。
