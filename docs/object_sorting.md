# 六物品分拣程序

程序：`scripts/object_sorting.py`。参数：`config/object_sorting.json`。
Ubuntu脚本：`scripts/run_sorting_ubuntu.sh`。
复用demo2已验证的YOLO、红外接近、舵机、停车、路径回退和异常红灯处理。
单球和单瓶demo已实机通过。当前正式分拣回位容差为5cm；2026-09-19一次整轮运行日志记录3球、3瓶均执行放置动作，最终回到外伸松爪状态。日志不能独立证明实际落位，仍需现场核对。
本轮完整输出见[terminal.log](../records/object_sorting/20260919/object-sort-19700101T011245258885Z/terminal.log)，结构化记录见[run.json](../records/object_sorting/20260919/object-sort-19700101T011245258885Z/run.json)；Jetson系统时钟未校准，所以运行目录时间戳为1970年。

## 回正还是直接搜索下一方向

每次抓取后内收，按接近路径倒车退回启动中心，再转向分类放置位。
放置后松爪并内收，从待取方位中选择与当前实际朝向转角最小的一个，直接转向它，到位后外伸识别。
位置和角度始终以程序启动时的中心、朝向为基准，不以放置后的朝向重新计算。
整轮结束先内收，再回到启动朝向，最后恢复外伸松爪。搜索中的预定角度和左右扫描角均先内收转向，再外伸取图；已锁定目标的5°视觉修正仍沿用demo2的外伸姿态。

## 一轮流程

1. 先设置抓夹侧ID2为raw1073，随后固定；底盘侧ID1外伸600，松爪。
2. 完成初态并确认停稳后记录中心及朝向，整轮不重设基准。
3. `pick_headings_degrees`列出六个大致方位：暂定0°、左36°、右36°、左后144°、右后144°、正后180°。
   每次按实际yaw选择转角最小的待取方位；转角按±180°环绕计算，转角相同时按配置列表顺序选择。实测小于约3°的转向难以产生位移，当前航向到位容差设为3°。
   需要转向时先内收、到位后外伸看正前方；启动时若已对准0°，直接看目标，不做多余内收。只锁定画面中心左右15%内最靠近抓取轴的目标。中心没有合适目标时在该方向左右15°内扫描，每次转向也先内收再外伸。两帧新图像均无合适目标才转到下一扫描角。
   该方向扫描完仍无可抓目标，就标为未找到，本轮跳过；每个配置方向最多抓一个物品。
4. 在球和瓶中选择最靠近抓取轴的目标，锁定后保持同类别和图像连续性。
   转向每步5°，死区±4%；只在当前抓取方向±25°内修正。目标连续丢失30帧后停止。
5. 居中后三次新红外读数均为正且≤24mm才夹紧；偏远时以4cm/s约1cm一步接近，最多20cm。
   此阈值是原始读数，不能解释为实际间隙2cm。
6. 夹紧后ID1内收1190，沿记录路径退回启动中心，容差5cm。
7. 球放右区、瓶放左区。两类各维护一个0至3的计数，按配置使用下一放置角度；
   用过的位不再使用，某类三个位置用完后不再选该类。
8. 转到放置角度，外伸、松爪释放，立即内收，确认停稳且未离开中心容差，再记录该位已用。
   将对应抓取方位标为已取，随后保持内收转到最近的待取方位，到位后外伸识别。
   待取方位处理完或六个位用完后先内收再回正，恢复初态。

方位状态在单次运行中维护并写入`run.json`：`pending`待取、`taken`抓放流程完成、
`not_found`未找到可抓目标。启动、选择下一方位、跳过方位、完成放置及结束时均记录状态快照。
例如右90°放完球后，优先比较剩余方位到当前右侧朝向的最短转角，而不是按固定列表回到左36°。
此改动只减少选择下一方位的转角，视觉对准、距离接近与回位参数沿用稳定版。

异常沿用demo2：请求停车、身体红灯，不自动回位或松开正在夹持的物品。
日志`work/object-sort-*/run.json`记录类别、位号、角度、数量、方位状态和是否放完六个；
`detections.jsonl`记录识别结果。动作反馈不能独立证明物品确实被夹住或放下，仍需现场核对。
某方向无目标不会被记为已放置，最后`all_six_placed=false`明确表示未完成六件。

## 三个固定放置位

`placement_headings_degrees`使用相对启动朝向的角度，SDK正值左转、负值右转。
暂定球区`[-90, -72, -108]`，瓶区`[90, 72, 108]`，依次为中间和两侧。
这六个角度已用于一次完整运行，仍可按地面落点调整。
底盘保持中心、机械臂外伸长度固定，因此三个落点在绕底盘的同一圆弧上。
试运行前应按实际落点调整区域与角度，留出物品宽度；仅改变角度不能改变放置半径。
用户已确定使用三个朝向区分放置位；抓取方向的36°排布仍是暂定值，应按实际摆放修改。

## 命令

```bash
cd ~/projects/3-LEARN
# 预览配置，不连接机器人
bash scripts/run_sorting_ubuntu.sh
# 只读识别球和瓶，不发送运动或LED命令
bash scripts/run_sorting_ubuntu.sh --observe --observe-frames 3
# 实际执行一轮
bash scripts/run_sorting_ubuntu.sh --execute
```

分拣程序同时识别两类，不使用demo2的`--target`单类别选项。
普通`yolo26m.pt`为默认模型。调整大致方位只需修改配置中的角度数组，实际抓取顺序由最近待取方位决定。
55项软件测试覆盖原demo和分拣调度，包括按放置后的朝向调度、±180°环绕选择、
方位状态记录与已处理方位排除、六个位依次分配、满区过滤、空方向跳过、
后方跨±180°的对准边界、搜索转向前内收和识别前外伸，以及原有运动和反馈检查。
